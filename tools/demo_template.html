Formal certification of a legal clause

Below are six synthetic contract sections generated from two agreed decision policies — some faithful, some carrying a single planted drafting flaw. The demo inspects the logic and runs the certification: every legally possible scenario is checked, and any divergence is returned as a concrete case where the contract and the policy disagree.

Pipeline Overview

1 · Reference logic

First we extract reference legal logic — boolean predicates ("dismissed for cause?", "5 years served?"), constraints, and named outcomes — plus a logic flow over it.

2 · Candidate clauses

Faithful clauses are the ones that obey reference logic exactly. Divergent clauses mutate the reference flow — flip a branch, drop a carve-out, promote a qualifier to a gate.

3 · Logic extraction from candidate clauses

The prose is mapped onto the reference logic, producing an extracted flow — the document's logic as the reader understood it.

4 · Certification (Lean)

Reference flow vs. extracted flow. Lean enumerates the counterexamples and the kernel checks the classification — counterexamples = [] or counterexamples.length = N — by decide. The proof object is machine-checked and formally verified.
