Certify a clause against the logic it was meant to implement.

Below are six synthetic contract sections generated from two agreed decision policies — some faithful, some carrying a single planted drafting flaw. Pick one, inspect the logic, and run the certification: every legally possible scenario is checked, and any divergence is returned as a concrete case where the contract and the policy disagree.

How it worksFour offline stages, one auditable pipeline

1 · Reference logic

Each legal domain gets a fixed ontology — boolean predicates ("dismissed for cause?", "5 years served?"), constraints ruling out impossible combinations, and named outcomes — plus a decision flow over it. A flow is a total function: every scenario reaches exactly one outcome.

Severance: 9 atoms, 7 constraints → 42 legally possible worlds of 512. Claims: 5 atoms → 32 worlds.

2 · Clause generation (offline)

Contract prose is LLM-authored from the flow. Faithful cases render the reference logic exactly. Divergent cases first mutate the flow — flip a branch, drop a carve-out, promote a qualifier to a gate — then render the mutated logic faithfully. Divergence lives in the tree, never in a model "making a mistake", so ground truth is exact by construction.

Divergent documents are reworded and renumbered against their faithful siblings: string diffing finds nothing. One flaw per case.

3 · Extraction (offline)

The prose is read back and mapped onto the same ontology, producing an extracted flow — the document's logic as the reader understood it. Because every case has recorded ground truth, extraction accuracy is measured, not assumed.

Current library: 6 of 6 documents extracted semantically exactly.

4 · Certification (Lean)

Reference flow vs. extracted flow, over every valid world. Lean enumerates the counterexamples and the kernel checks the classification — counterexamples = [] or counterexamples.length = N — by decide. No trust in our code required: the proof object is machine-checked.

Scope of the guarantee. The certification proves that two logic flows — the agreed reference and the flow extracted from the prose — agree or disagree on every legally possible scenario. It does not prove that extraction read the document correctly; that step is measured against ground truth (currently 6/6 exact) and stays auditable by a human. Open-textured terms ("material breach", "suitable alternative") live inside the predicates, where interpretation remains a human judgment. Proof artifacts: lean/cases/*.lean, Lean 4.32, core only, ~0.7 s per case.
